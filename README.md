Проект для института
Состоит из четырёх модулей
Описание модулей
1. EurekaServer - основной сервер, запускает реестр микросервисов на порту 8764
Его надо открыть после включения через http://localhost:8761/, что бы удостовериться что все сервисы поднялись
имеет основной одноимённый класс, с параметрами для запуска

2. Api-gateway - запускает шлюз общения между клиентом и микросервисами на порту 8080
Имеет 2 класса
Apigateway - основной класс с параметрами для запуска
RouteConfig - Класс-Настройщик маршрутов
Имеет две основые ветки, для остальных двух модулей
2.1 /api/hotels и /api/rooms, что нужны для связи с модулем hotelservice
2.2 /user/, /booking/ и /bookings/ для связи с модулем boockingservice

3. HotelService - модуль работы отелей и номеров, работает на порту 8082
Имеет несколько классов
hotelservice - основной класс, для запуска модуля с параметрами
Папка Controllers - слой обработки http-запросов
   3.1 HotelController - отвечает за CRUD-запросы эндпоинтам отелей
      3.1.1. /api/hotels - эндпоинт отелей
      3.1.2. /api/rooms  - эндпоинт комнат
      3.1.3 /api/rooms/recomemded - эндпоинт отелей
      3.1.4. createHotel - создаёт пользователя
      3.1.5 createRoom - Создёт комнату
      3.1.6 getHotels - возвращает отели
      3.1.7 getAvailableRooms - возвращает доступные комнаты
      3.1.8 getRecommendedRooms - возвращает свободные комнаты
   3.2 RoomController - отвечает за CRUD-запросы эндпоинтам комнат
      3.2.1 /api/rooms - эндпоинт комнат
      3.2.2 /api/rooms/{id}/confirm-availability - эндпоинт проверки на занятость комнаты
      3.2.3 /api/rooms//{id}/release - эндпоинт на освобождение комнаты
      3.2.4 RoomController - конструктор
      3.2.5 confirmAvailability - подтверждает доступность номера на указанные даты
      3.2.6 release - компенсация в hotelservice, в случае неудавшегося бронирования 
Папка entities - папка с моделями для базы данных 2H
   3.1 Hotel - модель Отеля
   3.2 Room - модель комнаты
Папка jwt - Слой работы с токенами
   3.1 JWTservice - сервис работы с токенами
      3.1.1. getKey -  а преобразует строку SECRET(ключ jwt) в объект SecretKey, который библиотека jjwt понимает и использует для криптографических операций.
      3.1.2. generateToken — создает JWT-токен, что живёт 1 час
      3.1.3. extractUsername — достает логин из токена
      3.1.4. extractRole — достает роль (USER/ADMIN) из токена
      3.1.5. isValid — проверяет подпись и срок действия токена
   3.2 AuthFilter - это фильтратор, который перехватывает каждый HTTP-запрос и проверяет наличие и валидность JWT-токена.
Папка repositories - хранит интерфейсы, для связи с базой данных
   3.1 HotelRepository - CRUD-Связь для отелей
   3.2 RoomRepository - CRUD-Связь для комнат
      3.2.1 - findByAvailableTrueOrderByTimesBookedAscIdAsc() - возвращает свободные номаера
      3.2.2 findByAvailableTrue(); -  возвращает свободные номера, отсортированные по timesBooked

5.  BookingService - модуль работы пользователей и бронирования комнат, работает на порту 8083
Имеет несколько классов
   4.1. boockingmain - основной класс, для запуска модуля с параметрами
   4.2. boockingservice - cервисный класс, который содержит ядро бизнес-логики для создания и управления бронированиями. Отвечает за взаимодействие с hotelservice и реализацию распределенной транзакции
    4.2.1. BoockingService - конструктор
    4.2.2. getRecommendedRooms -  возвращает список свободных номеров
    4.2.3. confirmAvailability - подтверждает доступность номера на указанные даты
    4.2.4 release - освобождает комнату, если бронь не удалась.
    4.2.5 createBooking - главный метод, помеченный @Transactional. Он реализует полный цикл создания бронирования:
Папка Controllers - слой обработки http-запросов
   4.1 AuthController - обрабатывает регистрацию через CRUD-запросы
      4.1.1. /user/register- эндпоинт регистрации
      4.1.2. /user/auth  - эндпоинт логина
      4.1.3 /user- эндпоинт операций с пользователем
   4.2 RoomController - обрабатывает создание брони через CRUD-запросы
      4.2.1 /booking - эндпоинт взаимодействия с брони
      4.2.2 /bookings - эндпоинт истории бронирования
      4.2.3 /booking/{id}- эндпоинт создания и удаления брони по id
Папка entities - папка с моделями для базы данных 2H
   4.1 User - модель пользователя
   4.2 Room - модель, что используется только для десериализации JSON-ответа от hotelservice
   4.3 Boocking - модель брони
Папка jwt - Слой работы с токенами
   4.1 JWTservice - сервис работы с токенами
      4.1.1. getKey -  а преобразует строку SECRET(ключ jwt) в объект SecretKey, который библиотека jjwt понимает и использует для криптографических операций.
      4.1.2. generateToken — создает JWT-токен, что живёт 1 час
      4.1.3. extractUsername — достает логин из токена
      4.1.4. extractRole — достает роль (USER/ADMIN) из токена
      4.1.5. isValid — проверяет подпись и срок действия токена
   4.2 AuthFilter - это фильтратор, который перехватывает каждый HTTP-запрос и проверяет наличие и валидность JWT-токена.
Папка repositories - хранит интерфейсы, для связи с базой данных
   4.1 HotelRepository - CRUD-Связь для отелей
   4.2 RoomRepository - CRUD-Связь для комнат
      4.2.1 - findByAvailableTrueOrderByTimesBookedAscIdAsc() - возвращает свободные номаера
      4.2.2 findByAvailableTrue(); -  возвращает свободные номера, отсортированные по timesBooked
    4.3 PasswordConfig - используется для хеширования в BoockingService
